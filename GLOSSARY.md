# Glossary

**Ticket**:
One tracked unit of work: type, status, blockers, acceptance criteria, progress log, evidence. ID `<feature>/NN`.
_Avoid_: task, story, card

**Evidence**:
The section of a ticket that proves the work: commits, PR, tests run, review findings, docs updated. Required before `done`.

**Frontier**:
Every `ready-for-agent` ticket whose blockers are all `done`.

**Gate**:
A deterministic CLI check that must pass before a phase can start: `gate spec`, `gate implement`, `gate release`.

**Tier**:
An install size (`small`, `medium`, `large`) listing the skills, roles, workflows, playbooks and scaffold a project receives.
_Avoid_: profile, preset

**Canonical**:
The source a file is generated from. `.agents/` is canonical; tool folders are adapters.

**Adapter**:
A generated, tool-specific copy of canonical assets (`.claude/agents/`, `.cursor/rules/`, ...).

**Managed file**:
A generated file carrying the `Generated by engr-toolbox` header. Sync and init may update it; deleting the header makes it project-owned.

**Project-owned file**:
A file the installer creates once and never overwrites (AGENTS.md, GLOSSARY.md, docs, tickets).

**Input**:
A document written by someone else (TDD, API spec, PRD), kept read-only in `docs/inputs/`.

**Drift**:
Changes to the code since the last sync point (`.ai/last-sync`) that may make maps, reference docs or ADRs stale.

**Acceptance criterion ID**:
`<feature>/<NN>#AC<n>`: how tests, manual cases and `trace` refer to one criterion.

**Scaffold**:
The project files under `template/` that `init` copies into a project.

## Flagged ambiguities

- "profile" (old) and "tier" (new) meant the same thing. Resolved: **Tier**.
- "TDD" meant both test-driven development (the `tdd` skill) and a team's Technical Design Document. Resolved: the skill is **tdd**; a team's design document is an **Input**.

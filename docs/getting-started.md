# Getting Started

## 1. Install

> **npm 12 and newer** block installs from GitHub unless you allow it, which is why the commands include `--allow-git=all`. Without it you get `EALLOWGIT`. Older npm versions accept the flag too.

Needs Node.js 18+. Run in your project folder:

```bash
npx --allow-git=all github:work-w-chrstnrpj/engr-toolbox
```

It asks four questions:

| Question | Choices |
|---|---|
| New or existing project? | `new`, `existing` |
| Size? | `small` (solo), `medium` (team), `large` (big codebase or many teams) |
| Which AI tools? (pick several) | ↑/↓ to move, Space to tick each tool you use, Enter to confirm. Claude Code, Codex, Cursor, Copilot, OpenCode, Windsurf, Cline, Kilo, Aider, Antigravity, OpenHands |
| Where do tickets live? | `local` (markdown in `tickets/`), `github` (Issues via `gh`), `other` |

5. **Where should skills and roles go?** `project` (default: committed in the repo, the whole team gets them) or `global` (once on your machine, shared by all your projects, like Matt Pocock's install). Project-specific files (AGENTS.md, glossary, docs, `qa/`, tickets, maps, the CLI) always stay in the project.

6. **CI/CD?** `none`, `test` (tests on PRs) or `release` (also release on merge to main), then branch names and release targets. Optional; change it later with `engr pipeline`.

Non-interactive: `npx --allow-git=all github:work-w-chrstnrpj/engr-toolbox init --yes --size medium --tools claude,codex,opencode --tracker local --pipeline test`

### Short command (optional, once per machine)

```bash
npm install -g --allow-git=all github:work-w-chrstnrpj/engr-toolbox
```

Then type `engr status`, `engr trace`, `engr --help-discover` in any project. It runs the project's own pinned copy in `.ai/cli/`. Without it, use `node .ai/cli/bin/cli.mjs <command>`. Inside Claude Code or Codex you type neither: use `/cli` or ask in plain words.

## 2. What you get

| Size | Adds |
|---|---|
| small | Ticket workflow, test-first build, review, glossary, ADRs, builder and reviewer roles |
| medium | Team documents (`docs/inputs`), design-first work (`docs/design`), the `qa/` layer (strategy, plans, cases, runs, traceability), triage, release checks, reference docs, context maps, architect, qa and sdet roles |
| large | Parallel spec builds, wayfinding for huge efforts, architecture surveys, deployment docs, heavy context tools |

Plus a copy of the workflow CLI at `.ai/cli/` so everything runs offline: `engr status`.

## 3. First steps

- **Existing project:** run `/adopt-project` in your AI tool. It builds the glossary, ADRs, architecture page and maps from your code. Then `/ingest` each team document (TDD, API spec).
- **New project:** fill the goal, stack and verification commands in `AGENTS.md`, then `/grill-with-docs`.
- **Lost?** `/next`. **What exists?** `/discover` (or `engr --help-discover-skillset`, `-workflow`, `-role`, `-docs`, `-structure`).

### Global install details

| What | Where |
|---|---|
| Shared skills, roles, workflows, policies | `~/.engr-toolbox/.agents/` |
| Claude Code | `~/.claude/skills/`, `~/.claude/agents/` |
| Codex | `~/.agents/skills/`, `~/.codex/agents/` |
| OpenCode | `~/.config/opencode/skills/`, `~/.config/opencode/agents/` |
| Cursor | `~/.cursor/skills/` |
| GitHub Copilot | `~/.copilot/skills/`, `~/.copilot/agents/` |
| Windsurf, Cline, Kilo, Aider, Antigravity, OpenHands | no known user folder: written into the project instead |

- Files this tool did not write are never overwritten, so another skill pack (for example Matt Pocock's `grilling`) stays as it is. The installer reports them as kept.
- Remove everything it installed globally: `engr uninstall --scope global` (add `--dry-run` to preview).
- Teams: prefer `project`, so the skills are versioned with the code and every teammate and CI gets the same ones.

## 4. Stay current

- Teammates changed code: `engr drift`, then `/update-docs`, then `drift --mark`.
- Changed a skill in `.agents/`: `engr sync`.
- Upgrade to a newer template: re-run the `npx` command with `init --yes`. Your saved choices are reused. Files you own (no `Generated by` header) are never touched.

## 5. CI/CD (optional)

**Easiest:** run `/setup-pipeline` in your AI tool. It asks what each branch should run (for example: feature → develop only tests; develop → main tests, build, tag and npm) and writes the YAML for you.

**Quick defaults:** answer question 6 during install, or any time later:

```bash
engr pipeline --mode test --write                                  # tests on every PR and push to develop
engr pipeline --mode release --release-targets release,npm --write   # also release on merge to main
engr pipeline --provider gitlab --mode release --write              # GitLab CI instead of GitHub Actions
engr pipeline --dev-branch none --write                              # feature → main, no develop branch
engr pipeline --mode none --write                                    # switch it off (removes the generated workflows)
```

It writes `.github/workflows/engr-checks.yml` and `engr-release.yml` (GitHub) or `.gitlab-ci.yml` (GitLab). A PR (GitLab: merge request) runs checks before code lands; a merge is the code landing, where releases run. Every PR runs install, test, build, `validate`, `sync --check` and the commit ticket check. A merge to main releases `v<version>` only when that tag doesn't exist yet. Details: `.agents/workflows/branching-and-release.md`, or run `/setup-pipeline` and the agent walks you through it.

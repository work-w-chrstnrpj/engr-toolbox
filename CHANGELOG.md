# Changelog

All notable changes to this project template are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [3.2.0] - 2026-11-07

### Added

- `gate deliver --ticket <id>`: a ticket's definition of done. Every acceptance criterion ticked; for code tickets every criterion named by an automated test; no open blockers; Commits and Tests evidence.
- `implement` keeps iterating (tests, full suite, review, docs, evidence) until `gate deliver` passes, and has explicit rules for bugs found along the way: fix your own, fix small touched ones with a regression test, raise the rest with `report-bug` (`Found during`), stop on blockers and S1.
- `loop` requires `gate deliver` as well as the verify command, retries with the exact failures as feedback, lists tickets raised during the run, and stops on an S1 bug. Bugs it raises start as `needs-triage` and are never worked automatically.
- `report-bug` moved to the small tier; `Found during` field on bug tickets.

## [3.1.0] - 2026-11-07

### Added

- Arrow-key pickers in `init`; AI tools are a multi-select (Space to tick several).
- Optional CI/CD: `pipeline` command and install question generate GitHub Actions for tests on PRs and pushes to the development branch, and releases on merge to main (GitHub Release, npm, Docker). Branches, commands and targets are configurable; releases only run for untagged versions.
- `release-version` and `release-notes` commands; `setup-pipeline` and `cut-release` skills; `branching-and-release` workflow.
- GitLab CI generation (`--provider gitlab`), provider detection from the git remote, `--provider other` for hand-written CI; `tag` (tag only) release target; `release` replaces `github` (still accepted).
- `/setup-pipeline` writes the YAML itself, with different steps per branch (tests only on feature → develop; tests, build, tag, release or packages on develop → main). `pipeline --custom` keeps hand-made workflows from being overwritten.
- npm 12 note: install commands use `--allow-git=all`.

### Removed

- `template/ci/github-actions.yml` (replaced by the generated pipeline).

## [3.0.0] - 2026-11-07

Renamed to **engr-toolbox**.

### Changed

- Package and install path: `npx github:work-w-chrstnrpj/engr-toolbox`.
- Short command `ais` → `engr`. Install record `ai-structure.json` → `engr-toolbox.json`. Global folder `~/.ai-structure` → `~/.engr-toolbox`. Env vars `AIS_*` → `ENGR_*`. Generated header `Generated by engr-toolbox`.
- Files with the old header and an old `ai-structure.json` are still recognised, so existing installs upgrade in place.
- `sync` now reports files it kept because they have no generated header.

## [2.2.0] - 2026-11-07

### Added

- `--scope project|global` for `init` and `sync`: shared skills, roles, workflows and policies can be installed once per machine (`~/.engr-toolbox/.agents/` plus each tool's user folder) while project-specific files stay in the project; `uninstall --scope global`.

### Fixed

- Managed-header detection missed headers placed after long frontmatter, and treated prose mentioning the header as a header; affected files were not updated by `sync`.

- Short `engr` command (global install from GitHub) that runs the project's pinned `.ai/cli/` copy; `cli` skill that lists and runs workflow commands inside coding agents.
- `discover` command and skill: list installed skills, roles, workflows, docs with status, structure and commands; `--help-discover-<topic>` flags; `--search`; detail view per item.

## [2.1.0] - 2026-11-07

QA engineering layer.

### Added

- `sdet` role (strategy, automation, CI tests, flaky tests, traceability, reports); `qa` now focuses on manual, exploratory, UAT and regression runs.
- Skills: test-strategy, test-plan, automate-tests, report-bug, fix-flaky-tests, test-report. Workflow: `quality.md`. Playbook: `sdet`.
- `template/qa/` scaffold (strategy, plans, cases, runs, test data, templates) in medium and large tiers.
- Acceptance criteria IDs (`feature/NN#ACn`), bug severity, `automation` ticket type.
- `trace` and `test-report --junit` commands; `gate release` blocks on uncovered or failing criteria, a red last run, and open S1/S2 bugs.

## [2.0.0] - 2026-11-07

Ticket-driven workflow.

### Added

- Owned workflow skills adapted from Matt Pocock's skills (MIT): grilling, grill-with-docs, to-spec, to-tickets, implement, implement-spec, tdd, code-review, diagnosing-bugs, triage, retro, pr, prototype, handoff, to-questionnaire, wait-what, domain-modeling, codebase-design, wayfinder, improve-codebase-architecture.
- New skills: tickets, next, adopt-project, ingest, design, mentor, coach.
- Ticket model with progress log and evidence; `status`, `gate`, `drift`, `check-commits`, `loop` commands.
- Interactive `init` installer with small, medium and large tiers, runnable as `npx github:work-w-chrstnrpj/engr-toolbox`.
- Node adapters for Copilot, Windsurf, Cline, Kilo, Aider and OpenHands; `sync --check`.
- `template/` scaffold: GLOSSARY.md, ADRs, `docs/inputs`, `docs/design` (ERD, flow, API templates), maps in arrow format, tickets board, CI example.
- Validator checks: skill calls, ADR supersede links, map paths, ticket status, blockers and evidence.

### Changed

- Nine roles reduced to four: architect, builder, reviewer (read-only), qa. Domain checklists moved to `roles/playbooks/`.
- Mentor and Coach overlays are now skills.
- A project's own `.agents/` is canonical after install; the CLI is copied to `.ai/cli/`.
- `update-docs` detects teammates' changes through `drift` and only proposes decisions.

### Removed

- plan-code-change, execute-code-change, write-automated-test-cases, investigate-issue (replaced).
- Product specification, development plan, TDD, project-structure and guideline placeholder docs (replaced by specs, tickets, architecture.md and ADRs).
- PowerShell scripts (replaced by the Node CLI).
